# Handover — project state

Written 2026-08-07. Read this first when picking the project up in a new session.

## What this is

Two repositories that together produce a Microsoft Defender for Endpoint health check report.

| Repo | Visibility | Contents |
|---|---|---|
| `MSalikoc/mde-data-collector` | **public** | `MDE-Collect.ps1`, `New-MdeApp.ps1`, `Test-Parse.ps1`. Runs at the customer. Produces **only** a JSON file |
| `MSalikoc/mde-health-check` | **private** | This repo. Report template, renderer, sample, Word version. Runs at the assessor's own machine |

The split is deliberate: the customer must never see an unreviewed draft report, and the
interpretation layer (best-practice library, narrative drafts, template) stays private.

## Pipeline

```
MDE-Collect.ps1  →  mde-data-<tenant>-<date>.json  →  MDE-Render.ps1  →  <Client>-MDE-Assessment-<date>.html
   (customer)              (plain text, editable)          (assessor)          (edit in browser → Ctrl+P → PDF)
```

Everything the renderer generates is wrapped in `<span class="draft">` and shows a yellow
**(REVIEW)** tag. The consultant clicks each tag (or Alt+click) to approve; there is also an
"Approve all" button. The toolbar counter shows how many remain.

## Where the report content comes from

- `secureConfiguration` (~130 rows of per-control compliance) is the richest source. It fills the
  antivirus, ASR, firewall, network, application and EDR tables, matched **by scid** — never by
  name, see the traps below.
- `asrRules` (from Intune policies) gives the ASR mode column; `asrEvents` gives audit counts.
- Findings are generated by threshold rules in the collector, then the renderer drops any that the
  configuration data contradicts and renumbers them.
- Domain maturity, licence entitlement, top findings, gap analysis, checklist status, compliance
  mapping and the priority matrix are all derived in the renderer.
- 34 of the 110 checklist rows are determined automatically; the rest stay "Not assessed" on
  purpose.

## Traps already paid for — do not rediscover these

1. **PowerShell variable names are case-insensitive.** `$scid = $null` blanked the `$SCID` lookup
   table on the first row and silently disabled a whole mapping pass. Never name a local the same
   as a table, whatever the casing.
2. **`Write-Host` inside a `[regex]::Replace` MatchEvaluator never reaches the console.** Collect
   evidence into a `$script:` list and print it after the replace.
3. **`Set-Chart` must run before the chart-filling pass** near the top of the renderer, otherwise
   the series is computed and thrown away.
4. **`ConvertFrom-Json` objects reject new properties.** Use `Add-Member` (that is what `Set-Chart`
   does) instead of `$d.charts.'New name' = …`.
5. **Assignments inside a function create a local copy.** Use `$script:html` in helper functions;
   top-level `if`/`foreach` blocks are fine.
6. **`[ordered]@{}` rows break `Select-Object -ExpandProperty` and `Measure-Object -Property`.**
   Any table processed by cmdlets inside the collector must be `[pscustomobject][ordered]@{}`.
   This crashed the whole collection the first time a tenant actually had ASR events.
7. **PowerShell treats smart quotes (U+2018/2019/201C/201D) as string delimiters.** A Turkish
   apostrophe inside a single-quoted string shifted every quote pair in the file. `Test-Parse.ps1`
   now warns about this.
8. **Match configuration controls by scid, not by name.** `'tamper'` matched "prevent tampering"
   (LDAP, 0%) instead of "Turn on Tamper Protection" (100%) and the report claimed tamper
   protection was disabled everywhere.

## Open items

- **App-only authentication is written but never executed.** `New-MdeApp.ps1 -AppOnly` adds Defender
  *application* permissions, grants them through `appRoleAssignments` and creates a client secret;
  `MDE-Collect.ps1` uses client credentials for the Defender resource when a secret is present. This
  exists because exposure score, recommendations and indicators failed at two tenants with
  `AADSTS50131` — a Conditional Access policy requiring a registered device, which a device code
  sign-in can never satisfy. Test it: the plumbing (app creation, consent, secret, token) can be
  proven on any tenant; the CA bypass itself can only be proven where the block exists.
- The private repo still carries a stale `MDE-Collect.ps1` with none of the collector fixes. Collection
  is done with the public repo, so it is unused — delete it or sync it.
- Sections that no API can fill: tenant/portal settings (data region, retention, preview features,
  alert notification rules), onboarding method per device, six-month trends (Advanced Hunting keeps
  30 days), AIR automation rates, Threat Analytics usage, Sentinel connector health. Decide whether
  to keep them in the template or cut them.
- `MDE-Health-Assessment-SAMPLE.html` was generated from an older template and lacks the newer
  toolbar and fills. Regenerate if it is going to be shown to anyone.
